fetchAllProjectsInGroup() ​

描述：获取某个组下所有项目（通过 GET /api/v3/groups/:id 接口，速度更快）。 当 includeSubgroups 为 true 时，会同时返回子组下的项目（sub_projects）。 兼容旧调用方式：返回值既是数组，又带有 projects 属性。

  • 旧方式：res.projects.map(item => ...)
  • 新方式：res.map(item => ...)

参数：

getGroupProjectsRecursive(options) ​

描述：递归获取某个组（含所有子组）下的全部仓库列表，支持多种过滤条件。 通过 GET /api/v3/groups/:id（include_subgroups=true）一次性获取 组及子组下所有项目，避免逐页遍历 /projects 接口，速度更快。

参数：

参数名类型描述
optionsobject输入配置
options.groupNamestring组名称或完整路径，如 'pmd-mobile'
options.privateTokenstring密钥
[options.baseUrl]string自定义 API 基础路径，如 https://git.woa.com
[options.filter]IGroupProjectFilter过滤配置

返回: Promise.<Array<IGroupProject>>

过滤后的仓库列表

示例

typescript
// 获取 pmd-mobile 组下所有仓库，排除 test 子组、归档仓库，以及前一天没有活跃的仓库
const yesterday = new Date();
yesterday.setDate(yesterday.getDate() - 1);

const projects = await getGroupProjectsRecursive({
  groupName: 'pmd-mobile',
  privateToken: 'xxxxx',
  baseUrl: 'https://git.woa.com',
  filter: {
    excludePathPrefixes: ['pmd-mobile/test/'],
    excludeArchived: true,
    lastActivityAfter: yesterday,
    filterFn: (project) => !project.name.startsWith('deprecated-'),
  },
});

console.log(projects);

resolveBaseUrl(baseUrl, path) ​

描述：处理 baseUrl，去掉尾部斜杠，并在 path 以 /api 开头时去掉 baseUrl 末尾可能重复的 /api/v3 后缀，然后拼接请求路径。 使用场景：tgit 中所有请求统一通过此函数拼接完整 URL，防止 baseUrl 末尾带 /api/v3 导致路径重复。

参数：

参数名类型描述
baseUrlstring基础路径，如 https://git.woa.com 或 https://git.woa.com/api/v3
pathstring请求路径，如 /api/v3/projects/xxx/merge_requests

返回: string

拼接后的完整 URL

示例

typescript
resolveBaseUrl('https://git.woa.com', '/api/v3/projects/xxx')
// => 'https://git.woa.com/api/v3/projects/xxx'

resolveBaseUrl('https://git.woa.com/api/v3', '/api/v3/projects/xxx')
// => 'https://git.woa.com/api/v3/projects/xxx'

resolveBaseUrl('https://git.woa.com/api/v3/', '/api/v3/projects/xxx')
// => 'https://git.woa.com/api/v3/projects/xxx'

// path 不以 /api 开头时，保留 baseUrl 末尾的 /api/v3
resolveBaseUrl('https://git.woa.com/api/v3', '/projects/xxx')
// => 'https://git.woa.com/api/v3/projects/xxx'

parseMRUrl(url) ​

描述：从 TGit MR 的 URL 中解析出项目名称和 MR ID iid 与 id 的区别：

  • iid：项目内的序号，从 1 开始递增，即 URL 和 Web 界面上看到的数字（如 /merge_requests/112 中的 112）
  • id：MR 在整个 TGit 系统中的全局唯一 ID，不同项目间不重复

本函数从 URL 中解析出的数字是 iid（项目内序号），不是全局 id。 如需获取全局 id，可使用 queryMRByIId 通过 iid 查询 MR 详情后获取。

参数：

参数名类型描述
urlstringTGit MR 的 URL，如 https://git.woa.com/group/project/-/merge_requests/112

返回: Object | null

解析结果（mrIid 为 URL 中的 iid），解析失败返回 null

示例

typescript
// URL 中的 112 是 iid（项目内序号）
parseMRUrl('https://git.woa.com/pmd-mobile/ai-tool/rd-ai-common/-/merge_requests/112/notes')
// => { projectName: 'pmd-mobile/ai-tool/rd-ai-common', mrIid: '112' }

parseMRUrl('https://git.woa.com/coecology/xd/-/merge_requests/169')
// => { projectName: 'coecology/xd', mrIid: '169' }

queryMRByIId(options) ​

描述：根据 iid（项目内序号）查询 MR 评审信息 iid 与 id 的区别：

  • iid：项目内的序号，从 1 开始递增，即 URL 和 Web 界面上看到的数字（如 /merge_requests/112 中的 112）
  • id：MR 在整个 TGit 系统中的全局唯一 ID，不同项目间不重复

对应 API：GET /api/v3/projects/:id/merge_request/iid/:merge_request_iid/review

参数：

参数名类型描述
optionsobject输入配置
options.projectNamestring项目名称或项目全路径
options.privateTokenstring密钥
options.mrIidstring合并请求在项目中的编号 iid（即 URL 中看到的数字）
[options.baseUrl]string自定义 API 基础路径

返回: Promise.<object>

MR 评审信息，包含 id（评审记录全局 ID）、reviewable_id（reviewer/summary 接口需要的 ID）、iid、title、description、author 等字段

示例

typescript
queryMRByIId({
  projectName: 'coecology/xd',
  privateToken: 'xxxxx',
  mrIid: '169',
}).then((resp) => {
  console.log(resp.id);    // 全局 id
  console.log(resp.title); // MR 标题
})
